LyriCue song-search backend — one-time setup
Written 2026-09-01, rewritten 2026-09-15 when this backend was switched
from AI web search to a search over the curated community song library.

WHAT THIS IS
A small Cloudflare Worker (backend/ in this repo) that the app's Search
screen calls. It searches a shared community Dropbox account (a separate
account from Rusty's own personal one, holding a curated ~7,800-song
ChordPro library — see "chordpro songs/project notes.txt" Step 10 in the
LyriCue - audio prompter folder) and returns matching songs, then serves
up the actual file content when one is picked. The app's UI never mentions
Dropbox anywhere — it's just called "Search."

WHAT YOU NEED, AND WHERE TO GET EACH ONE

1. A Cloudflare API token, so GitHub Actions can deploy the Worker for you.
   In the Cloudflare dashboard: My Profile > API Tokens > Create Token >
   "Edit Cloudflare Workers" template. Copy the token value.
   Also grab your Account ID — it's shown on the right-hand side of the
   main Cloudflare dashboard.

2. A long-lived Dropbox refresh token for the community library account.
   Log into that Dropbox account (rusty@yourblindally.com) in a private
   browser window, then visit lyricue.net/reveal-token.html and connect —
   it'll show a refresh token, copy it. Disconnect right after, since that
   same page's Dropbox connection is shared with the Lyric Editor and
   Setlist Builder web tools.

3. A shared secret you make up yourself — any random string of letters and
   numbers works, it just has to match in two places (step 5 below). This
   is what stops a stranger who somehow finds the Worker's URL from
   running searches against the community library through your account;
   it is not real per-user login, just a basic lock.

WHERE EACH VALUE GOES

4. In this GitHub repo: Settings > Secrets and variables > Actions > New
   repository secret. Add two:
     CLOUDFLARE_API_TOKEN    (from step 1)
     CLOUDFLARE_ACCOUNT_ID   (from step 1)
   Once these exist, push to master (or run the "Deploy song-search
   backend" workflow manually from the Actions tab) and it will create the
   Worker on Cloudflare for the first time.

5. After that first deploy, go to the Cloudflare dashboard > Workers &
   Pages > cueme-song-search > Settings > Variables and Secrets, and add
   these as Secrets (not plain variables, since these are all sensitive):
     APP_SHARED_SECRET                your made-up string from step 3
     COMMUNITY_DROPBOX_REFRESH_TOKEN  the token from step 2

6. Same place as step 4 (GitHub repo Settings > Secrets and variables >
   Actions), add two more repository secrets — these names are unchanged
   from the earlier AI-search version of this backend, they mean the same
   thing (a backend URL and a matching shared secret), just kept as-is to
   avoid re-touching GitHub settings:
     AI_SEARCH_BACKEND_URL — the Worker's address plus "/search". You'll
       find the base address on the Worker's own page in the Cloudflare
       dashboard, right under its name — something like
       "https://cueme-song-search.<your-subdomain>.workers.dev". Add
       "/search" to the end.
     AI_SEARCH_APP_SECRET — must be typed exactly the same as
       APP_SHARED_SECRET from step 5.
   These are NOT put directly into src/search/config.ts, on purpose — this
   repo is public, and a real secret committed there would be readable by
   anyone on GitHub. The build workflow writes them into that file at
   build time, straight into the CI runner's copy, never into git history
   — see the "Inject search backend config" step in each build workflow.
   Until these two secrets exist, the Search screen just shows a friendly
   "not set up yet" message instead of trying to call anything.

TRYING IT
Once all of the above is done: open the app, Library > Search, type a
title or artist, tap Search. Tapping a result downloads it straight into
your library, same as picking a song from your own Dropbox browse screen
— nothing else to confirm, since these are real curated files, not
AI-generated ones that might need review.

HISTORY: WHAT THIS REPLACED, 2026-09-15
The original version of this backend asked an AI provider (Gemini,
Anthropic, or OpenAI, picked via an AI_PROVIDER secret) to search the open
web and extract lyrics/chords from whatever page it found. Real-world
testing found its success rate genuinely low even after several rounds of
fixes (a two-call search-then-extract split, a mechanical completeness
gate, domain-blocking known-bad sources) — see git history on this file
and on backend/src/index.ts for that whole story if it's ever worth
revisiting. Replaced outright with the community library search above,
which is both more reliable (it's real curated content, not scraped) and
doesn't carry the same copyright-sourcing concerns. If the AI_PROVIDER /
GEMINI_API_KEY / ANTHROPIC_API_KEY / OPENAI_API_KEY secrets are still set
on the Worker from the old setup, they're simply unused now — safe to
remove from the Cloudflare dashboard whenever, nothing depends on them.
